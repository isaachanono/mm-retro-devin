Retos

Devin Desktop Workshop · Mexico Tech Week · devin-mastermind-retro

Un Mastermind de consola en Java 8, sin librerías y con su propio runner de tests. Es pequeño a propósito: cabe entero en la cabeza de un agente, así que lo interesante es qué decisiones tomas tú cuando Devin te las pregunta. Hay cinco retos; no tienes que hacerlos todos.

Cómo trabajar cada reto

Entiende (dale contexto con @-menciones), planea (Plan mode), actúa (Implement) y verifica (tests, Quick Review, Merge).

Antes de empezar

Necesitas java y javac (Java 8 o más nuevo). No hay Maven, ni Gradle, ni npm: todo es javac y java.

java -version
javac -version

macOS / Linux: compila y corre los tests con este comando (en la raíz del repo):

mkdir -p build/classes build/test-classes && javac -d build/classes -encoding UTF-8 src/com/mastermind/*.java && javac -cp build/classes -d build/test-classes -encoding UTF-8 test/com/mastermind/*.java && java -cp build/classes:build/test-classes com.mastermind.TestRunner

Jugar (macOS / Linux): java -cp build/classes com.mastermind.MastermindGame

Windows: build.bat, run.bat y test.bat. Si el repo ya trae test.sh, también puedes usar ./test.sh.

Reglas

  1. Empieza cada reto en Plan mode. Lee el plan, corrígelo y solo entonces aprieta Implement.
  2. Las decisiones de diseño son tuyas. Si Devin asume algo que no te gusta, dilo en el plan, no después.
  3. Una sesión por reto. Para los retos Paralelo usa Worktree y revisa con Quick Review antes del Merge.
  4. Que Devin corra los tests y te enseñe el resultado. Si dice "listo" sin mostrar la salida, pídele la salida.
  5. Regla de oro de este repo: una clase de tests nueva compila pero no corre hasta que la registras en test/com/mastermind/TestRunner.java (y en test.bat, o test.sh si existe). Pide ver el [PASS] de tus tests nuevos.

Ojo con esto

  • El juego es de consola y usa colores ANSI. Si tu terminal no los muestra bien, no pasa nada: el nombre del color siempre se imprime.
  • Si ya hiciste la demo en vivo, tu repo puede tener ya los niveles de dificultad. El reto 1 sirve igual: te pide una variante más grande.
  • Cuando pruebes a mano el reto 2, ejecútalo desde una carpeta temporal para no ensuciar el repo con archivos de puntajes.

Retos

Ruta sugerida (~60 min): 1 → 2 → 3. Si vas rápido, 4 o 5. Los dos últimos son para quien termine antes.

  1. Niveles con nombre (Core, 15–20 min)
  2. High Scores (Core, 15–20 min)
  3. Semilla y atajos (Paralelo, 20–25 min)
  4. Cliente-servidor (Jefe, 25–35 min)
  5. Bonus: la IA que juega sola (Jefe, 25–30 min)

Reto 1 · Niveles de dificultad con nombre

Core · 15–20 min · Plan mode, Declarar rangos, Tests

La demo dejó dos preguntas. Ahora convierte la dificultad en algo con personalidad: Fácil, Normal, Difícil y Personalizado.

La misión

Al arrancar, una sola vez, el juego pregunta el nivel. Cada nivel cambia al menos el número de intentos (hoy son 10) y si el código secreto puede repetir colores. También puede cambiar la longitud y el número de colores.

Enter sin escribir nada elige Normal, que debe comportarse exactamente como el juego de hoy. Una entrada inválida vuelve a preguntar y nunca gasta un intento. El texto "You have N attempts" debe reflejar el nivel.

Si ya hiciste la demo: tu repo ya pregunta longitud y colores. Parte de ahí y agrega los niveles con nombre, los intentos y la regla de repetición encima.

Una ayudita para arrancar

Es solo el comienzo. Escribe tu propio prompt y complétalo con lo que pide la misión.

Quiero niveles de dificultad con nombre (Fácil, Normal, Difícil y Personalizado) en @src/com/mastermind/MastermindGame.java. Entra en Plan mode y dime los valores de cada nivel y qué rangos aceptas, antes de tocar código.

Lo que tú decides

  • ¿Qué valores tiene cada nivel (intentos, longitud, colores, repetición sí/no)? Que el plan los declare en una tabla.
  • ¿Qué rangos acepta Personalizado para cada valor? Que el plan diga "acepto de X a Y".
  • Sin repetición, ¿qué pasa si hay menos colores que posiciones? ¿Se rechaza al preguntar, o revienta al generar el código?
  • ¿El nivel se pregunta de nuevo en "Play again?" o solo una vez por ejecución?

¿Cómo sabes que terminó?

  • mkdir -p build/classes build/test-classes && javac -d build/classes -encoding UTF-8 src/com/mastermind/*.java && javac -cp build/classes -d build/test-classes -encoding UTF-8 test/com/mastermind/*.java && java -cp build/classes:build/test-classes com.mastermind.TestRunner
  • printf '\nRED RED RED RED\n' | java -cp build/classes com.mastermind.MastermindGame

Archivos que vas a ver

src/com/mastermind/MastermindGame.java src/com/mastermind/ConsoleInterface.java src/com/mastermind/GameLogic.java src/com/mastermind/ColorPalette.java test/com/mastermind/GameLogicTest.java

Si te atoras

Pista 1
Busca MAX_ATTEMPTS en GameLogic: no existe como constante. El 10 está escrito dentro del constructor sin argumentos.
Pista 2
Piensa en el orden: el nivel se pregunta antes de construir GameLogic, y ConsoleInterface crea su propio Scanner(System.in). Dos Scanner sobre el mismo stdin se roban líneas.
Pista 3
Un diseño que funciona: un enum Difficulty con los valores de cada nivel, un constructor de GameLogic con maxAttempts y allowRepeats, y validar colores >= longitud cuando no hay repetición.
Trampas conocidas (al final)
  • El constructor de ConsoleInterface crea su propio Scanner(System.in). Si creas otro para el menú, con entrada por pipe pierdes líneas.
  • ColorPalette tiene siete colores fijos y la lógica espera RED, BLUE, GREEN, PURPLE en ese orden. Si necesitas un octavo color (ORANGE), agrégalo al final sin romper new ColorPalette().
  • getRandomColor() usa Math.random(). Para "sin repetición" no sirve: hay que barajar o muestrear sin reemplazo, y con menos colores que posiciones se cicla o revienta.
  • Una clase de test nueva no corre hasta que la registras en TestRunner. Si agregaste tests en GameLogicTest, ya corren.

Reto 2 · High Scores por nombre de jugador

Core · 15–20 min · Plan mode, Persistencia, Tests con stdin

Guarda quién ganó y con cuántos intentos. Los puntajes se muestran justo antes de salir.

La misión

El juego pide un nombre, guarda las victorias en un archivo y, antes de salir, muestra la tabla de mejores puntajes. No hay base de datos ni librerías: Java 8 y un archivo de texto.

La parte difícil no es escribir el archivo. Es decidir qué significa "mejor puntaje", qué pasa con los empates y con las derrotas, y qué significa "antes de salir" cuando el jugador cierra la terminal con Ctrl+D.

Recomendado: haz antes el reto 1. Con niveles, el ranking tiene sentido por dificultad. Si no lo hiciste, el ranking es uno solo.

Una ayudita para arrancar

Es solo el comienzo. Escribe tu propio prompt y complétalo con lo que pide la misión.

Quiero High Scores por nombre de jugador, que se muestren antes de salir. Lee @src/com/mastermind/MastermindGame.java y entra en Plan mode: antes de escribir código, pregúntame todo lo que haya que decidir.

Lo que tú decides

  • ¿Dónde vive el archivo y cómo se evita subirlo a git? (El directorio desde donde ejecutas, tu carpeta de usuario, junto a las clases…)
  • ¿Qué es "mejor"? ¿Solo menos intentos, o una dificultad mayor vale más? ¿Ranking global o por dificultad?
  • Empates: ¿gana quien llegó primero, se comparte posición o se desempata por otra cosa?
  • Derrotas: ¿se registran o no? ¿Qué es un nombre válido (vacío, con espacios, mayúsculas, muy largo)?
  • "Antes de salir": ¿solo con n en Play again, o también si cierras stdin con Ctrl+D?

¿Cómo sabes que terminó?

  • mkdir -p build/classes build/test-classes && javac -d build/classes -encoding UTF-8 src/com/mastermind/*.java && javac -cp build/classes -d build/test-classes -encoding UTF-8 test/com/mastermind/*.java && java -cp build/classes:build/test-classes com.mastermind.TestRunner

Archivos que vas a ver

src/com/mastermind/MastermindGame.java src/com/mastermind/ConsoleInterface.java src/com/mastermind/HighScores.java (nuevo) test/com/mastermind/TestRunner.java .gitignore

Si te atoras

Pista 1
Separa la persistencia en su propia clase pequeña. Piensa en qué momento del flujo ya conoces nombre, intentos y dificultad, y en qué momento "salir" realmente ocurre.
Pista 2
Pide el nombre una sola vez al inicio de run(), guarda solo en la rama de victoria de playGame(), y muestra la tabla en un finally alrededor del ciclo de play-again para cubrir tanto n como EOF.
Pista 3
playGame() llama reset() y luego generateSecretCode(): fijar el secreto antes se pierde. Para el test por stdin, subclasea GameLogic y sobreescribe generateSecretCode().
Trampas conocidas (al final)
  • Clase de test nueva sin registrar en TestRunner, test.bat y test.sh: compila, no corre y todo se ve verde.
  • File.createTempFile exige un prefijo de al menos 3 caracteres; con "hs" revientan los tests.
  • Si el EOF ocurre en "Play again?", main puede salir con System.exit(1) antes de mostrar la tabla, a menos que la muestres en un finally.
  • Tests que reemplazan System.in o System.out deben restaurarlos en un finally; si no, contaminan al resto de la suite.
  • Un formato con comas se rompe con nombres que llevan comas. Elige un separador que el nombre no pueda contener, o escapa.

Reto 3 · Dos frentes: semilla reproducible y atajos de teclado

Paralelo · 20–25 min · Worktree, Paralelo, Quick Review, Merge

Dos agentes, dos zonas del código, un solo Merge. Ninguno debe pisar al otro.

La misión

Dos funciones independientes. Sesión A: poder jugar con una semilla (--seed 42) y que el mismo número dé siempre el mismo código secreto. Sesión B: aceptar las iniciales de los colores como atajo (R B G P en vez de RED BLUE GREEN PURPLE).

Abre cada una en su propia sesión Worktree. Cuando las dos terminen, haz Quick Review de cada diff y luego Merge. Las dos sesiones comparten una trampa: quien registre su clase de tests en TestRunner o test.bat choca con la otra. Decidan quién lo hace al final.

Dos sesiones, dos zonas

SESIÓN A · SEMILLAInyectar un Random con semilla en vez de Math.random(). Leer --seed en main.
src/com/mastermind/ColorPalette.java src/com/mastermind/MastermindGame.java
SESIÓN B · ATAJOSAceptar la inicial de cada color al capturar el guess, junto con el nombre completo.
src/com/mastermind/ConsoleInterface.java test/com/mastermind/ConsoleInterfaceTest.java

Una ayudita para arrancar

Es solo el comienzo. Escribe tu propio prompt y complétalo con lo que pide la misión.

Sesión A (Worktree)

Quiero poder jugar con --seed para reproducir el código secreto (@src/com/mastermind/ColorPalette.java usa Math.random). Plan mode primero. No toques ConsoleInterface: otra sesión trabaja ahí.

Sesión B (Worktree)

Quiero escribir los guesses con iniciales (R B G P) en @src/com/mastermind/ConsoleInterface.java. Plan mode primero. No toques ColorPalette ni MastermindGame: otra sesión trabaja ahí.

Lo que tú decides

  • A: ¿Dónde se crea el Random? Si lo creas con la semilla en cada ronda, todas las rondas repiten el mismo código.
  • A: ¿Qué hace --seed sin valor, con letras o con un número fuera de rango: error claro o ignorar?
  • B: ¿Qué pasa si la inicial es ambigua? Hoy todas las iniciales son únicas, pero la paleta es extensible.
  • B: ¿Se puede mezclar R blue G PURPLE en una misma línea?

¿Cómo sabes que terminó?

  • git diff --stat
  • mkdir -p build/classes build/test-classes && javac -d build/classes -encoding UTF-8 src/com/mastermind/*.java && javac -cp build/classes -d build/test-classes -encoding UTF-8 test/com/mastermind/*.java && java -cp build/classes:build/test-classes com.mastermind.TestRunner

Si te atoras

Pista 1
Si el Merge choca, casi seguro es la lista de clases de test. Resuélvelo a mano: deja las dos clases.
Pista 2
Para la semilla, el lugar natural del Random es donde hoy está Math.random().
Pista 3
Para los atajos, parseGuess en ConsoleInterface concentra todo el cambio.
Trampas conocidas (al final)
  • Crear new Random(seed) por cada ronda hace que todas las rondas repitan el mismo código.
  • Las iniciales (R, B, G, P, Y, C, W, O) son únicas hoy, pero un color nuevo como BROWN chocaría con BLUE.
  • Las dos sesiones editan la misma línea de test.bat o de TestRunner si registran su clase de tests: conflicto garantizado.

Reto 4 · Jefe: cliente-servidor

Jefe · 25–35 min · Megaplan, Arquitectura, Tests de integración

Saca la lógica del juego a un servidor. El cliente solo pregunta y muestra. Todo en Java 8 y sin librerías.

La misión

La lógica (el secreto, los intentos, la calificación) vive en un servidor. El cliente de consola solo captura el guess y pinta la respuesta. El JDK ya trae lo necesario: busca com.sun.net.httpserver y HttpURLConnection.

La regla que lo hace interesante: el secreto no puede viajar al cliente mientras la partida siga en curso. Y el servidor valida todo, aunque el cliente ya valide.

Si lo vas a hacer, pide un megaplan. Mejor un plan profundo que 400 líneas que no entiendas.

Una ayudita para arrancar

Es solo el comienzo. Escribe tu propio prompt y complétalo con lo que pide la misión.

Quiero separar este juego en un servidor (la lógica) y un cliente de consola, solo con lo que trae el JDK, Java 8. Pide un megaplan: el protocolo y la estructura de paquetes, y espera mi visto bueno antes de escribir código.

Lo que tú decides

  • ¿Qué protocolo? HTTP/REST con com.sun.net.httpserver o sockets con un protocolo de líneas.
  • ¿Cómo identifica el servidor cada partida (un id en la ruta, un token) para atender a más de un cliente?
  • ¿Cómo manejas el JSON sin librería? Mínimo para lo que viaja, no un parser completo.
  • ¿Cuándo se revela el secreto? Solo al perder. ¿Y si el cliente abandona?
  • ¿Dónde viaja la dificultad (longitud y colores)? ¿Fija por ahora o en el cuerpo de "crear partida"?

¿Cómo sabes que terminó?

  • mkdir -p build/classes build/test-classes && javac -d build/classes -encoding UTF-8 src/com/mastermind/*.java && javac -cp build/classes -d build/test-classes -encoding UTF-8 test/com/mastermind/*.java && java -cp build/classes:build/test-classes com.mastermind.TestRunner

Archivos que vas a ver

src/com/mastermind/server/ (nuevo) src/com/mastermind/client/ (nuevo) test/com/mastermind/ (test de integración) build.bat y test.bat (para compilar subpaquetes)

Si te atoras

Pista 1
Piensa en dos programas: uno es dueño del juego (secreto, intentos, calificación) y otro solo pregunta y muestra. Antes de tocar código, decide qué mensajes se intercambian y qué no puede viajar nunca.
Pista 2
El servidor puede reusar GameLogic tal cual, con una instancia por partida identificada por un id. Para probar sin puerto fijo, haz que el servidor acepte puerto 0 y te diga en cuál quedó. Para que el test no dependa del azar, inyecta una fábrica de GameLogic con secreto fijo.
Pista 3
Tres rutas bastan: crear partida, mandar un intento y consultar el estado. El servidor responde 400, 404 o 409 según el caso, y el secreto solo aparece si el estado es perdido.
Trampas conocidas (al final)
  • Assertions exige un mensaje en cada aserción (assertTrue(boolean, String)); una sobrecarga sin mensaje no existe.
  • El secreto es aleatorio (Math.random() sin semilla). Sin una fábrica inyectable, el test de integración solo puede probar el camino de perder, o es intermitente.
  • Ocupar un puerto lanza BindException. Si no la capturas, sale un stack trace largo en vez de un mensaje.
  • Un test que necesita un servidor ya corriendo en el puerto 8080 no es un test: el TestRunner no lo levanta por ti.
  • Un JSON completo con reflexión son cientos de líneas. Para este protocolo basta con leer un arreglo de colores.

Reto 5 · Bonus: la IA que juega sola

Jefe · 25–30 min · Megaplan, Refactor, Benchmark

Escribe un solver que adivine el código y mide en cuántos intentos lo logra en promedio.

La misión

Un solver que juega contra el juego: en cada turno elige un guess que sea consistente con todas las respuestas anteriores. Después, un benchmark que corra cientos de partidas con una semilla fija y reporte el promedio y el máximo de intentos.

El cuello de botella no es el algoritmo. GameLogic.scoreGuess descuenta un intento y depende del código secreto de la instancia: no sirve para probar candidatos. Necesitas una función pura de calificación, y reusarla desde scoreGuess sin romper nada.

Una ayudita para arrancar

Es solo el comienzo. Escribe tu propio prompt y complétalo con lo que pide la misión.

Quiero un solver que juegue solo y un benchmark de intentos promedio. Lee @src/com/mastermind/GameLogic.java y dime en Plan mode cómo calificarías candidatos sin gastar intentos.

Lo que tú decides

  • ¿Qué significa "determinista"? ¿El primer candidato consistente en orden, o uno aleatorio con semilla?
  • ¿Dónde pones la calificación pura: método estático en GameLogic o clase aparte?
  • ¿Qué tamaño de espacio de búsqueda aguantas? 8^6 son 262,144 candidatos; ¿cuándo dejas de enumerar?

¿Cómo sabes que terminó?

  • mkdir -p build/classes build/test-classes && javac -d build/classes -encoding UTF-8 src/com/mastermind/*.java && javac -cp build/classes -d build/test-classes -encoding UTF-8 test/com/mastermind/*.java && java -cp build/classes:build/test-classes com.mastermind.TestRunner

Si te atoras

Pista 1
Primero mueve la lógica de calificación a una función estática que reciba secreto y guess. Haz que scoreGuess la use. Corre los tests antes de seguir.
Pista 2
Un solver simple: mantén la lista de candidatos y, tras cada respuesta, quédate solo con los que darían la misma calificación contra tu guess.
Pista 3
Para el benchmark reproducible, inyecta un Random con semilla fija y juega N partidas contra códigos generados con él.
